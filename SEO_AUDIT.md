# MacEx SEO audit

Audit and implementation of 15 November 2026. It covers https://macex.app (marketing pages, docs, guides, comparison, feature pages) and the journal at https://macex.app/blog/.

## How to read this

- **Measured** means a tool produced the number in this session. The tool and conditions are named.
- **Hypothesis** means a judgement that was not checked against data. No search-volume or ranking data was available in this session: no Search Console, Ahrefs, Semrush or DataForSEO access, and the keyless PageSpeed Insights API had used up its daily quota.

## 1. What the audit found

The site was already in good technical shape. The SEO checker built in this session (`scripts/seo.py check`), run against the code as it was before any changes, found **1 error and 4 warnings**. The error was a stale sitemap. Every page already had a unique title, a meta description, a self-referencing canonical, one `<h1>`, Open Graph tags, valid JSON-LD and the analytics script. Live checks found no broken redirects.

### Stack

- Plain HTML, CSS and JS on Cloudflare Pages. There is no build step. Every push to `main` deploys.
- The blog is generated by `scripts/build_blog.py` from `content/posts/*.json`. A daily agent publishes posts, and the `build-blog.yml` workflow regenerates and commits the output.
- All pages are server-delivered HTML. Crawlers don't need JavaScript to read any content. Only the in-browser demo is rendered by JS, and its content is supplementary.

## 2. Changes, by file

### Technical SEO

- `scripts/seo.py` (new, standard library only):
  - `sitemap` regenerates `sitemap.xml`. It lists every page that has a self-referencing canonical and no `noindex`. `<lastmod>` is the newest `dateModified` or `datePublished` in that page's JSON-LD, so a page's date lives in one place.
  - `sitemap --check` fails if the sitemap is stale.
  - `check` validates every HTML page. It checks `lang`, the title, viewport, the Umami script, JSON-LD syntax, and image `alt`/`width`/`height`. For indexable pages it also checks the canonical against the file path, the meta description, exactly one `<h1>`, the `og:*` and `twitter:card` tags, and that `og:url` equals the canonical.
  - It also checks structured data: required Article, BlogPosting, SoftwareApplication, BreadcrumbList and VideoObject fields, and every Offer price against `config.js`.
  - Across the site it checks for duplicate titles and descriptions, broken internal links and `#anchors` (honouring `_redirects`), missing trailing slashes, sitemap coverage in both directions, and `robots.txt`.
  - `check --live` fetches the deployed sitemap. It checks that each URL returns 200 with a matching canonical and no `noindex`, the http/www/slash redirects, the real 404, `/thanks/` `noindex`, and `robots.txt`.
- `scripts/test_seo.py` (new) runs the checker on the repository and on fixtures with deliberate mistakes, so the checker itself is tested.
- `.github/workflows/validate-blog.yml`, now "Validate site", runs on every push and pull request: unit tests, blog freshness, sitemap freshness and the SEO check.
- `.github/workflows/build-blog.yml` replaces its inline sitemap patch with `seo.py sitemap` and runs `seo.py check` before it commits.
- `sitemap.xml` is regenerated: 12 URLs, all with `<lastmod>`.
- `_redirects`: `/features` and `/features/` go to `/#features` with a 301. There is no features index page on purpose; see section 4.

### Homepage (`index.html`, `style.css`, `app.js`, `config.js`)

- Title: `MacEx – Finder Alternative & File Manager for Mac` (49 characters). Description: "Find any file on your Mac by describing it, preview without opening, remove duplicates, tidy Downloads and free up space. Native macOS app, one-time $9.99." (154 characters). The social description is aligned, and `twitter:image:alt` is added.
- JSON-LD: a `WebPage` node with `dateModified`. `SoftwareApplication` gains `applicationSubCategory`, `downloadUrl` and `installUrl`. No ratings, reviews or download counts were added; none exist.
- Hero copy: "MacEx is a file manager for Mac." This is the same length as before, so the line break and design are unchanged.
- The "at a glance" list now links Natural search, Free Up Space, Duplicates and Smart Downloads to their deep pages, plus a second "How MacEx search finds files" link.
- New FAQ: "Is there a free trial?" It is answered truthfully, from the app's licensing code.
- The footer Guides column links both feature pages. Blog links are now relative (`blog/`).
- Performance: `<link rel="preload">` for the hero mascot (the LCP image). The video posters use `data-poster` and are set by `app.js` only when the features section comes within 900 px of the screen.
- Accessibility: feature panels are now `<div role="tabpanel">`, and the footer wordmark has `role="img"`.
- Analytics: `config.js` adds `data-umami-event="checkout"` or `"download"`, plus `data-umami-event-place` (the section: header, pricing, download, main), to every `data-buy` and `data-download` link. Umami's tracker counts these clicks. No new script, cookie or personal data is involved.

### New feature pages (screenshots of the real app; content verified against `~/Projects/MacEx` source and README)

- `features/file-search/`:
  - Primary intent: find a file on a Mac when you don't know its name or folder.
  - Covers how the parser maps type, date, size and source words to editable chips; text search in screenshots and PDFs (on-device Vision, off by default); searching by download source; Quick Search, Shortcuts actions and `macex://` links.
  - An explicit **limitations** section: no visual understanding, missing metadata excludes files, library scope and the 20,000-file cap, online-only iCloud files, OCR misses. It also says when Spotlight or `mdfind` reach further.
- `features/storage-management/`:
  - Primary intent: free up Mac storage safely.
  - Starts with what macOS Storage settings already offer.
  - A table of every Free Up Space group with its exact rule (100 MB, age threshold of 30–365 days), how cleanup stays reversible (Trash, 500-item history, no permanent delete), and why freed space can differ (Trash, APFS clones, snapshots, compression, hard links).
  - Also covers what it doesn't touch (`~/Library`, caches, online-only files) and the optional automation rules.
- Both pages have a unique title, description, canonical, OG and Twitter tags, Article and BreadcrumbList JSON-LD, related links, and a CTA to checkout plus the in-browser demo.

### Existing pages improved

- `compare/finder/` is the Finder-alternative page. The new title is `MacEx vs Finder: A Finder Alternative for Finding Files on Mac`.
  - A new section explains how MacEx differs from dual-pane managers (ForkLift, Path Finder, Commander One, QSpace). It is honest that those suit move-heavy work better, and lists the file-manager basics MacEx does have (Split View with F5/F6, folders, rename, Trash, SFTP).
  - Also new: a Home screenshot, related links and an updated `dateModified`.
- `guides/find-duplicate-files-mac/`:
  - Explains how matching works (SHA-256, then a final byte check; hard links are review-only) and adds a screenshot.
  - Adds a "without an app" section: the Photos Duplicates album on Ventura and later, and Finder sorting.
  - Adds related links.
- `guides/clean-up-downloads-folder-mac/`: Tidy and Downloaded From screenshots, a "without an app" Finder method, and related links.
- `article.css` (new): the identical inline `<style>` blocks from three pages are moved into one shared file. Breadcrumb and date text use the darker `--muted` color for contrast, the breadcrumb link is underlined, and figure and related-link styles are added.
- Screenshots: 900 px variants (`assets/app/*-900.jpg`, 42–76 KB, against 140–253 KB for the originals) served with `srcset`/`sizes`, all lazy-loaded with intrinsic `width`/`height`.

### Blog (`scripts/build_blog.py`, `content/posts/*.json`, `BLOG-PUBLISHING.md`)

- New optional `image` field (src, width, height, alt, caption), validated at build time. It replaces the slug-specific code path, and the generated HTML for that post is unchanged.
- New optional `related_pages` field: links to macex.app guides and feature pages, rendered as "Related MacEx guides". All four posts now link to the relevant feature or guide page, and the feature pages link back.
- Related stories prefer the same category, then the newest.
- The Blog JSON-LD node gets `dateModified`.
- The generator no longer writes `blog/_headers`, `blog/_redirects` or `blog/robots.txt`. The root `_headers` already holds the blog rules. The publishing doc now says that slug redirects go in the root `_redirects`.
- No post was removed or rewritten. Tests cover the new fields.

### Documentation

## 5. Remaining opportunities, by priority

1. **Self-host the three font families, with metric-matched fallbacks** (`size-adjust`, `ascent-override`). This also fixes the open CLS issue in section 3. Google Fonts CSS blocks rendering, and it is the main remaining LCP cost (about 1 s on throttled mobile). Hosting WOFF2 subsets locally with `font-display: swap` and preloading the two above-the-fold weights would cut a third-party connection. Test the hero carefully, because its animated `<h1>` uses Manrope and Instrument Serif.
2. **Homepage main-thread work.** About 3 s of "Other" and paint work on mobile comes from continuous decorative animations: the aurora blurs, the marquee and the floating cards. Pausing them while offscreen, or after a few seconds, would help battery and INP without changing how the page looks at first.
3. **A pricing-intent page or section with refund and licence terms.** Searchers comparing paid utilities look for refund policy, device limits and update terms. Only the owner can state the refund policy, so it was not invented here.
4. **More real-app screenshots** for preview, Quick Search and Connections. These could support future pages such as "Quick Look alternative" or "SFTP client for Mac", but only if each topic gets real depth.
5. **Article images for blog posts** using the new `image` field, plus a per-post `og:image` in PNG or JPEG. SVG isn't supported by most social platforms.
6. **Shorter blog titles.** Ask the daily agent to keep `title` at or under 60 characters; the generator adds "— MacEx Journal".
7. **Docs `dateModified`** is 2026-11-11 while the content mentions 0.8.1 and Homebrew. When the docs next change, update the JSON-LD date and the "Updated" line together.
8. **Earn links.** Rankings for "Finder alternative" depend largely on being included in the roundup lists that fill that results page (alternativeto.net, ftp-mac.com, MacStories-style reviews). Submitting MacEx to AlternativeTo and to Mac app directories is the most direct off-site step.

## 7. Keywords and topics

### What was validated

The only check possible here was qualitative: US web search results on 15 November 2026. No volumes were measured.

- **"Finder alternative for Mac"**: the results are listicles ("best Finder alternatives", AlternativeTo, Eltima, Beebom). They feature ForkLift, Path Finder, Commander One, QSpace, Marta and Double Commander. Intent is commercial comparison of dual-pane file managers. MacEx is a different kind of app, so ranking on its own page is unlikely; inclusion in those lists is the realistic route.
- **"How to find files on Mac when you forgot the name"**: the results are how-to guides from Apple Support, CleanMyMac, TechRadar and Eltima. Intent is informational, which suits `features/file-search/` and the journal.
- **"Free up storage space on Mac"**: the results are how-to guides, mostly from cleaner-app vendors (MacPaw, Cindori, Avast) and Apple. Intent is informational with commercial undertones. MacEx's review-first angle sets it apart.
